## 1. Purpose

G2.3B establishes the **minimum read-only production visibility** required for
identity **I2 — Production Diagnostics**, so agents can diagnose production
without the founder becoming the log reader, account configurator, credential
courier, schema investigator, Edge Function inventory auditor, branch-protection
verifier, or production diagnostics technician.

The Founder approves **access boundaries** and the **exact provisioning plan**.
Agents perform authorized technical mechanics later under separate exact
authorizations.

**G2.3B must never grant:** deployment, migration, database writes,
production-data mutation, credential-value access, financial authority,
customer-communication authority, security-control changes, or destructive
authority.

Plan **dedicated identity I2 — Production Diagnostics**. Do **not** use founder
personal accounts, shared admin credentials, unrestricted service-role

## 8. Edge Function reconciliation plan

**Authoritative repo root:** `command-center/supabase/functions/` (exclude
`_*`). Legacy/root copies are classified separately and must not inflate the
primary inventory.

**Compare fields:** name; repo presence; hosted presence; deploy timestamp;
version/source identity where available; auth requirement; callers (repo
grep); apparent purpose; ownership; status class.

**Status classes:** `reconciled` | `hosted-only` | `repository-only` |
`duplicate-or-legacy` | `unknown` | `high-risk`.

**Mandatory high-risk labels** for financial, communication, SQL-execution,
authentication, and destructive functions (including but not limited to:
`execute-sql`, `stripe-webhook`, `payment-webhook`, `create-payment-intent`,
`send-sms`, `send-invoice`, `send-estimate`, `money-loop-delete`).

**Outputs:** machine-readable inventory JSON/YAML + human-readable summary in
`RECONCILIATION_G2-3B.md` (references only; no log dumps).

**Prohibited during G2.3B:** delete, redeploy, disable, or modify any function.

- Produce machine-readable + human-readable drift report

- State whether drift **blocks G2.3C**
- **Never** auto-repair; **never** apply migrations

## 12. Log and sensitive-data controls

Logs may contain: customer names, addresses, emails, phones, auth identifiers,
request payloads, financial metadata, tokens, cookies, authorization headers,
stack traces, database details.

**Binding controls:**

1. Minimum necessary access for the investigation
2. Mask before any evidence is copied outside the platform UI
3. **No raw logs** in Decision Packets, Batons, Ledgers, Markdown, or chat
4. No secret values anywhere in repo/chat artifacts
5. No unnecessary customer-data retention
6. Prefer **references** to platform-native log locations (project, time range,
   request id) instead of duplication
7. **Stop and escalate** if logs expose unexpected sensitive data beyond the
   investigation need
8. Evidence retention: masked excerpts retained ≤ **30 days** unless an open
   incident/Ledger entry requires longer; then delete or re-mask at close

Policy text lives in `DIAGNOSTICS_ACCESS.md` (proposed).

## 17. Revocation and rollback plan

- **B1 rollback:** clean `git revert` of the B1 PR; zero production impact.
- **B2–B5 rollback:** revoke I2 tokens/roles immediately; remove secret-store
  entries; demote/remove platform members; record in Ledger.

  **stop**, declare incident, do not continue under G2.3B authorization.

## 18. Stop conditions

Stop implementation or provisioning when any of:

1. Read-only permissions cannot be technically enforced
2. A token grants broader rights than approved
3. A personal or shared admin login is required for standing I2 use
4. Secret values must be placed in repository files or prompts
5. Logs expose unmasked sensitive data into artifacts
6. Write operations are possible through the diagnostics identity
7. Edge Function inventory cannot be reconciled or formally attested
8. Schema drift cannot be bounded
9. execute-sql risk remains unknown after the review window
10. Branch-protection state cannot be verified or attested
11. Audit attribution is unavailable
12. Credential revocation cannot be demonstrated
13. Scope expands into deployment, migration, or data repair
