### Binding platform constraints (official docs)

1. **Personal account repositories have no read-only collaborator role.** Collaborators get pull **and** push.
2. Therefore a dedicated machine user invited to `faydog127/BHFOS` **necessarily** receives write at the GitHub identity layer.
3. **`GITHUB_READ_ONLY=1` is insufficient** when the underlying identity has write access — it is an MCP filter, not GitHub authorization.
4. Fine-grained PATs are scoped to a **resource owner** the token creator controls (own user or member org). They are **not** a reliable way for a second personal account to hold exact least-privilege access to this user-owned repo.
