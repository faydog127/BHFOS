## 5. Exact Supabase endpoints proposed (adapter allowlist)

Adapter may call **only**:

| Purpose | Proposed Management API path | Notes |
| --- | --- | --- |
| Project status | `GET /v1/projects/{ref}` | Metadata only |
| Health | `GET /v1/projects/{ref}/health` (service health) | Non-sensitive health |
| Edge Function inventory | `GET /v1/projects/{ref}/functions` | **List/metadata only** — adapter must **never** call `/body` |
| Migration status | `GET /v1/projects/{ref}/database/migrations` | Only if available without partner-only / over-scope; else omit and defer |
| Bounded logs | Fixed adapter-defined retrieval using log endpoints **without** accepting agent-supplied SQL | Predefined windows/sources; mask before return |

## 6. Supabase endpoints and capabilities prohibited

Adapter and credential must deny / never expose:

- Custom log SQL from the agent
- `execute_sql` / arbitrary SQL / `database_read` / `database_write`
- `apply_migration` / DDL
- `GET .../functions/{slug}/body` (function-body retrieval)
- `deploy_edge_function` / `edge_functions_write`
- Secrets / API-key list or read
- Customer table data; Auth-user data
- Configuration mutation
- Service-role credentials
- Unrestricted official Supabase MCP toolset against production
