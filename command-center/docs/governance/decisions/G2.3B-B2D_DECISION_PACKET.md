## Operational problem
Production Diagnostics needs least-privilege Supabase metadata access through the
repo adapter (`command-center/tools/supabase-diagnostics-adapter/`). No Supabase
credential has been issued. Official unrestricted Supabase MCP against production
remains prohibited. Prior B2B options assumed agent-visible OAuth tokens; B2C
replaced that with adapter-first.

## Proposed correction
Authorize **at most one** issue option below for an **adapter-internal**
credential. Store the value only in the Production Diagnostics secret store.
Inject only into the adapter process env as `SUPABASE_DIAGNOSTICS_ADAPTER_TOKEN`.
Never place the value in chat, repo, Markdown, Baton, Ledger, MCP global config,
CLI argv, or agent-visible tools.

## Exact identity
| Field | Value |
| --- | --- |
| Credential type | **OAuth2** Management API app token (fine-grained) — **not** PAT, Dashboard Read-Only member, or service-role |
| Inventory name | `SUPABASE_DIAGNOSTICS_ADAPTER_TOKEN` (names only) |
| Consumer | Supabase diagnostics adapter process only |
| Scope | Production project only |
| Storage | Diagnostics secret store → adapter env only |
| Audit | OAuth app / adapter identity (not founder-personal PAT) |
| Revocation | Revoke OAuth app authorization; rotate client credentials; stop adapter; clear Diagnostics env |
| Explicitly prohibited | PAT; Dashboard Read-Only member; service-role; `secrets:*`; `database_read` / `database_write`; `edge_functions_write`; Auth-user browsing; config mutation; agent-held raw token |

## Adapter technical ceiling (already on main)
Allowlisted (when corresponding platform permission exists):
- `GET /v1/projects/{ref}` — project status
- `GET /v1/projects/{ref}/health` — health metadata

Allowlisted but **requires Option B** platform permission:
- `GET /v1/projects/{ref}/functions` — list/metadata only; adapter **must not** call `/body`

Unavailable / deferred (adapter enforces):
- Migration list — `unavailable` until account capability proven
- Bounded logs — `deferred` until separate Founder auth (no agent-supplied SQL)
- All paths matching prohibited substrings (`/body`, `/secrets`, SQL, deploy, etc.)

## Issue options (choose one)

### Option A — Minimal (recommended)
| Field | Value |
| --- | --- |
| Platform permissions | `projects:read` / `projects_read` only |
| Enables via adapter | Project status + health |
| Does not enable | Function inventory, logs, SQL, secrets, writes, `/body` |
| B3 negative tests (later) | secrets list, SQL, function deploy, `/body` → expect denial |

### Option B — Add function inventory (accepts source-body platform risk)
| Field | Value |
| --- | --- |
| Platform permissions | Option A **plus** `edge_functions_read` |
| Enables via adapter | Function **list/metadata** only (adapter deny `/body`) |
| Founder must accept | Platform still technically allows `GET .../functions/{slug}/body` if something bypasses the adapter |
| B3 negative tests (later) | Confirm adapter denies `/body`; record platform `/body` risk as accepted |

### Option C — Deny / defer
Issue **nothing**. Leave `SUPABASE_DIAGNOSTICS_ADAPTER_TOKEN` unverified. B2
remains incomplete for Supabase until a later packet.

### Explicitly not offered in this packet
- `analytics_logs_read` — requires a **separate** packet (sensitive logs)
- `database_migrations_read` — partner-gated / unproven
- `database_read` — forbidden
- Hostinger Diagnostics credential — forbidden (unavailable / Operator-only)
- B3 live connection campaign — **not** authorized here
- GitHub Administration permission — **not** authorized here

## Access granted
Only the single option the Founder authorizes (A, B, or C).

## Access not granted
Hostinger I2 for Diagnostics; B3–B5; deployment; migration; financial actions;
communications; any secret values in repo/chat/Markdown.

## Blocking findings
None that prevent **choosing Option A**. Option B requires explicit acceptance of
non-excludable platform body-read if the adapter is bypassed.

## Known limitations
- Adapter deny is a process control, not a platform ACL for Option B body risk
- Live adapter→Supabase read proof is **B3**, not B2D
- Migration list may remain unavailable without partner entitlement

## Rollback / revocation
Revoke OAuth app authorization; delete/rotate client credentials; stop adapter;
clear Diagnostics env; mark inventory name revoked.

## Recommendation
Authorize **Option A only**. Defer `edge_functions_read` and all log permissions.
