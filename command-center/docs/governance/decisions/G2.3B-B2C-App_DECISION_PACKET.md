## Release

- **PR context:** #54 (implementation artifacts); App create/install is external

## Operational problem
Cursor Diagnostics needs least-privilege GitHub access. A machine-user PAT cannot
provide read-only identity on this **User-owned** repo. Official Cursor GitHub MCP
expects a token env var; a **GitHub App** with a protected launcher can mint
short-lived installation tokens without granting collaborator write.

## Proposed correction
Authorize Founder to create/install a **private dedicated GitHub App** and store
App credentials only in the Diagnostics secret environment; authorize Builder to
implement a protected launcher + Diagnostics-only MCP wiring that injects
**installation access tokens only** (never the App private key) into the MCP
process.

## Exact GitHub App design

| Field | Value |
| --- | --- |
| App type | Private GitHub App |
| Owner (interim) | Founder account (`faydog127`) — App owned by founder for now |
| Installation | **Only** `faydog127/BHFOS` |
| Attribution | App / installation identity (not founder-personal PAT; not user-to-user OAuth acting as founder) |
| User authorization | **None** — installation tokens only; no “act on behalf of user” flow |
| Inventory names | `I2_GITHUB_APP_ID`, `I2_GITHUB_APP_INSTALLATION_ID`, `I2_GITHUB_APP_PRIVATE_KEY` (names only; values in Diagnostics secret store) |
| Launcher | Protected local/Diagnostics-only launcher generates short-lived installation access token and sets `GITHUB_PERSONAL_ACCESS_TOKEN` for MCP child process only |
| MCP | Official GitHub MCP; `GITHUB_READ_ONLY=1`; toolsets `context,repos,pull_requests,actions` |
| Revocation | Uninstall App from repo and/or disable App; delete Diagnostics secret-store entries |

### Exact repository permissions (read-only)

| Permission | Access |
| --- | --- |
| Metadata | Read |
| Contents | Read |
| Actions | Read |
| Pull requests | Read |
| Commit statuses | Read |
| Administration | Read **only if** still required for branch-protection/ruleset evidence after measuring public ruleset API; otherwise omit |

### Explicitly prohibited App permissions

All write permissions; Workflows write; Actions write; Secrets; Variables;
Administration write; contents write; PR write; any org-wide install.

## Access granted
- Founder: create private App, set permissions above, install **only** on
  `faydog127/BHFOS`, place App ID / installation ID / private key in
  **Production Diagnostics** secret store only.
- Builder: implement launcher + update Diagnostics MCP templates to use launcher
  (no secret values in repo); isolation tests; PR update.

## Access not granted

- App private key in chat, Markdown, global MCP, Operator/Release/UAT envs
- B3–B5 live campaigns; deployment; migration; G2.3C–E

deferred.
